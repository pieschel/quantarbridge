# QuantarBridge v0.1.4

Direct BrandMeister audio now uses IMBE/AMBE speech-parameter conversion in
both directions. The release includes the settings confirmed in live radio
listening tests on 19 September 2026: P25 to DMR gain adjustment 1.58;
DMR to P25 spectral scale 4.0 and gain adjustment 1.0. Each call resets its
codec state; invalid frames are handled without reusing an earlier call.

## Settings that appeared to disappear

The native BrandMeister dashboard profile does not configure a BREW audio
restart target. Previously, saving a password, talkgroup mapping or dynamic
timeout still requested that target. The resulting error rolled the entire
settings transaction back, while the independently stored dashboard password
remained intact. This failure is reproduced by a regression test and fixed.

The dashboard service now allows the narrowly scoped sudo restart commands
already supplied by the image. Configuration writes flush both file contents
and directory entries. Setup rejects volatile/overlay/read-only storage and
flushes its completed configuration. The SSH welcome text no longer falsely
states that every configured installation still needs setup.

## Image validation

The ARM64 build runs codec boundary, damaged-frame and call-reset tests,
dashboard/configuration tests and password-based SSH/sudo checks. Generated
configuration and authentication files are compared byte-for-byte after
unmounting/remounting the image filesystem; all test settings are removed
before packaging. See PERSISTENCE-CHECK.txt and SSH-LOGIN-CHECK.txt.

A physical Raspberry Pi reboot and RF test of this new image have not been
performed. The tester's precise cause is not confirmed without device logs;
the reproducible dashboard rollback is fixed.

Initial SSH login: `qbadmin` / `quantarbridge`. Change the initial password
with `passwd`, then run `sudo quantarbridge-setup` once. Preserve existing
station settings before flashing: flashing replaces the SD card contents.

The direct codec controls are in the two `dvmbridge-*.yml` files under
`system`. Existing dashboard PCM audio gain controls do not calibrate the
direct parameter-conversion path. Disable the corresponding `direct*` flag
to intentionally return to the earlier PCM path.
